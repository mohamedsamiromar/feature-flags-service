# 0018 — Server-side SDKs download the ruleset, pinned by generated conformance vectors

**Status:** Accepted. It supersedes [0009](0009-bootstrap-returns-evaluated-results.md)
for server-side SDKs.

## Context

A server-side SDK evaluates thousands of users per process, inside its own request path.
One network hop per user context, as in 0009, is the cost to remove. Local evaluation
means every SDK reimplements the engine, and any divergence silently serves the wrong
value (SDK_CONFIG_SPEC §1).

## Decision

`GET /sdk/flags/config/` ships the raw ruleset to server keys, with `config_version` as
its ETag. `sdk_conformance_vectors.json` is generated by running the engine over the
fixture in `apps/evaluation/conformance.py`, and CI checks that it is current. The
fixture uses explicit pks, because rule-level bucketing is salted with the rule id.

## Consequences

- The two bulk endpoints are not alternatives. The bootstrap is for one user per session;
  the config download is for many users per process.
- Any change to evaluation behaviour changes the vectors, and their diff is the reviewable
  record that an SDK contract moved.
- The vectors are never edited by hand.
